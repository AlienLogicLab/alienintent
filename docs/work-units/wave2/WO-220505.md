### FX-B2 fixture — pinned commands, inputs and expected outcomes

Policy: `LivenessPolicy(grace_seconds=300, interval_seconds=60, confirmation_seconds=90)`
— the design defaults (`docs/evidence/wave2-design-contracts.md:1007`), unchanged.

1. **Prelaunch admission / seed** — write the real authority state record (aggregate
   `fx-b2-operational-authorization`, `{"schema_version":1,"active":true,"epoch":1,
   "invocation":"<launch-id>"}`) and the seeded `KnownActive` record for
   `FX-B2-PROBE-<launch-id>` via the real store `commit`/journal `enter` calls used by
   `HostedMonitor`. Expected: both durable records readable back before launch; this is the
   prelaunch admission boundary (an invalid/missing record must refuse launch, not fabricate
   one — `HostHold`).
2. **Launch (real transport, real process)** —
   `python3 -m alienintent.composition.monitor_host launch --config fx-b2-supervision.json
   --actor factory-director --authority fx-b2-operational-authorization`. Expected: a real
   `systemd-run` unit starts `host --launch-id <id>`; `HostedMonitor.start()` runs; a
   manager-owned timer independently invokes `observe` every `interval_seconds`.
3. **Dropped-trigger recovery within G+I** — wait real wall-clock time past
   `grace_seconds` (>=300s) and confirm within one further `interval_seconds` (<=360s total)
   that the host's own scan cycle has produced a durable `liveness.gap` ->
   `liveness.recovery_intent` -> `liveness.readback_confirmed` sequence for the seeded
   record (read back directly from `liveness.sqlite`, not inferred from process exit).
   Expected: recovery detected inside G+I, gated on `bound_claim == "G_PLUS_I_CLAIMED"`
   (healthy monitor).
4. **Provider/judgment block suppression, attributed resolution** — before or instead of
   step 3, record a real `CorrelatedOutcome` of kind `FOUNDER_EXCEPTION` for the seeded
   record via `StoreLifecycleJournal.record_outcome`; confirm across >=2 real grace periods
   that no recovery intent is admitted (`liveness.suppressed` only) and exactly one
   attributable C1 `JUDGMENT` attention item exists. Then resolve it through the real
   `AttentionPort.resolve(...)` with matching actor/authority/lane; confirm this permits
   reinspection only (no auto-relaunch) and that an actual new-generation
   `journal.enter(...)` transition is required before any recovery intent is admitted again.
5. **Delayed delivery and restart duplicate safety** — once a durable intent exists for an
   expected effect (after step 3's gap, before its readback settles), send SIGTERM to the
   supervised host unit and run
   `python3 -m alienintent.composition.monitor_host restart --config fx-b2-supervision.json
   --actor factory-director --authority fx-b2-operational-authorization --replaces <old-id>`.
   Expected: exactly one effective consumer record for that effect after restart (read back
   via `store.readback_guarded`); a delayed/duplicate original-delivery attempt against the
   same effect key afterward is refused `EFFECT_IDENTITY_USED`, never a second action.
6. **One-writer confirmation** — attempt a second concurrent `launch` against the same
   profile/unit while the first is active; expected refusal `HOST_NOT_OWNED` /
   `HOST_OUTSIDE_OWNED_UNIT` (the existing ownership fence, not new code).
7. **Exact real outcome readback** — `python3 -m alienintent.composition.monitor_host show
   --config fx-b2-supervision.json` plus a direct `store.readback_guarded` read for the
   settled effect's receipt digest/invocation/effect-id; retain these verbatim in the
   evidence record together with exit statuses and immutable observation refs, per the
   existing evidence-obligations contract above.
