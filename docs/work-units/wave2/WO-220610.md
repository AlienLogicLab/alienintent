returned CLARIFY on two owner-level acceptance questions, correctly noting SF-REQ-053
does not itself answer either (SF-REQ-053's own text governs persistent control-plane
episode tenure and durable attention — it does not enumerate trajectory-capture anomaly
classes or a restart-loss boundary). These are bounded implementation-scope decisions for
this prerequisite node, not new product requirements or Founder-reserved architecture
policy; the Factory Director disposes them here, conservatively, per the Founder's
existing `FULL_WAVE2_BIU_UNBLOCK_AUTHORITY` grant ("The Director is the current owner for
these decisions").

1. **Anomaly classes and response.** The composition must detect: sequence gaps,
   out-of-order events, duplicate identities, timestamp regressions, and capture stalls
   (no event observed within a configured interval). On detection, the composition
   records a durable anomaly evidence record (append-only, same store as captured
   events); it does not alert or halt. Alerting/halting policy is an operational decision
   outside this bounded node's scope.
2. **Restart-loss boundary.** This node's own guarantee covers only events the
   composition has already accepted (durably recorded) at the moment of restart: those
   must survive without loss or duplication. Events a live source might emit while the
   composition process is down are explicitly out of this node's scope — recovering
   those requires a replayable/buffered upstream source contract that no node currently
   owns, and inventing one here would expand this node beyond "build the composition
   B1 can integrate" into a new, unauthorized capability. This mirrors the existing C5
   precedent (`monitor_host` restart "preserves generation and pending state", not
   downtime-emitted external events). FX-B1P's fixture therefore feeds synthetic events
   directly to the composition and only asserts survival of already-accepted events
   across the kill/restart cycle; it does not simulate a buffered external source.
   Whether B1's eventual operational-target proof needs a buffered source is B1's own
   separately authorized question, not this node's.

Local/self-supervised exercise is sufficient for this BIU's own DONE. It does not itself
close WO-220504/Issue #124's separately authorized target-profile gap; it removes the
"the capability does not exist" ground that gap currently rests on partly, leaving only
genuine external target-binding as WO-220504's own remaining question.
