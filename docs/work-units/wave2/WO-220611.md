## Acceptance criteria / completion predicate

Implement, at the canonical `FactoryCoordinator._run -> admit_release` call site, real
enforcement such that:

- a release request with no durable release authorization record is refused, zero actors
  launched;
- a release request naming no exact baseline is refused, zero actors launched;
- a release request naming a baseline that does not resolve to a real repository revision
  (e.g. the null revision) is refused, zero actors launched;
- a release request naming a baseline not reachable/ancestral from the intended release
  point is refused, zero actors launched;
- a release request carrying explicit unsuperseded denial/refusal wording is refused,
  zero actors launched, even if other fields are otherwise valid;
- no worker is launched until all of the above checks pass;
- the existing canonical `admit_release` checks (replay/fingerprint, policy/source,
  digest, dependency, capability, budget) continue to pass their own existing tests
  unchanged;
- `FactoryCoordinator` is given a real, attributable per-BIU budget/limit input (not a
  hard-coded `1`) drawn from the execution allocation, and a release request whose
  attributable allocation for a required budget dimension is exhausted is refused by the
  existing `admit_release` budget check (`release.py:76-78`), zero actors launched.
