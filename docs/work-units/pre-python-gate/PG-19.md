# PG-19 — EOS conformance normalization audit and FD-06 disposition

**Type:** documentation-only governance BIU spanning ALL-EOS (P000) and AlienIntent.

**Baseline:** AlienIntent `727de90685ebdd6cca48f61fd9b1948efc8bbc33`, clean `main`.
ALL-EOS `AlienLogicLab/P000-all-eos` (private repository) at
`79d769228c266064e71b7ab7f556ea831cfc9537`, clean `main`.

**Authority:** Architecture Authority §40, which requires AlienIntent to record
one internally consistent, approved EOS version/commit before claiming
conformance, states that mixed per-document maturity is not a conformance
baseline, and requires maturity inconsistencies to be reconciled in EOS itself
first. Founder direction on FD-06 withdraws the earlier mixed-maturity pin
recommendation. Within EOS, the applicable existing authority is DR-000001
(Accepted), `docs/05-artifacts/record_directories_and_numbering.md` (Accepted
v0.1), `docs/00-foundation/ontology.md` (Accepted v0.1), `AGENTS.md` and
REVIEW-000001 (Accepted).

**Outcome:** audit every EOS artifact relevant to AlienIntent inheritance,
enumerate every inconsistency that prevents EOS from being represented as one
coherent approved version, record a normalization plan durably in EOS, apply
only those corrections already authorized by existing EOS authority, and record
in AlienIntent that no EOS conformance baseline exists until the remaining
inconsistencies are resolved by Founder decision.

**Excluded:** Python code, scaffolds or implementation BIUs; Node source, tests,
configuration, runtime, services or bootstrap behaviour; FactoryChecks;
promotion of any draft, scaffold, directed-but-unratified or proposed EOS
material; creation of an EOS version identity; GitHub mutation; push to any
remote; deployment, credentials, provider spending.

**Acceptance:**

1. The canonical EOS repository and revision are identified with evidence.
2. Every EOS artifact relevant to AlienIntent inheritance is inventoried with
   its current authority/status and its ratified-vocabulary mapping.
3. Every inconsistency preventing a single coherent approved EOS version is
   enumerated with artifact, problem, proposed correction, correction class
   (editorial, semantic, architectural, governance) and whether Founder
   approval is required.
4. Corrections applied inside EOS are limited to those already authorized by
   existing accepted EOS authority, each citing the authorizing rule.
5. No draft, scaffold, proposed or directed-but-unratified EOS material is
   promoted, and no EOS governance rule is weakened.
6. History and provenance are preserved: superseded material stays in place and
   links forward; no prior evidence is rewritten without a reviewable trail.
7. AlienIntent records that it has no EOS conformance baseline, withdraws the
   earlier candidate mixed-maturity pin with provenance, and states the exact
   Founder decisions required to establish one.
8. The FD-06 entry, the G31 gate row, the gate report and the validation record
   are consistent with that result; the 34-row matrix remains complete; the
   2 PASS / 0 DEFERRED / 32 BLOCKED counts are unchanged.
9. Agent-Ready and independent review are recorded before any local commit; no
   push occurs in either repository.
