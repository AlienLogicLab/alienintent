# Candidate work sequence — Python factory builds AlienIntent

**Status:** Draft decomposition. The old handoff packet received an Agent Ready READY result for earlier text, but that result does not apply to any current packet. The first proposed code task is now fixed-contract publication. It and each later unit need Founder design review and assessment of their exact text before release. Use the current Python code where it already works; the PY-10 sandbox proved prepared-work execution, automatic refill and restart with six seeded tasks.

During the [hand-fed build period](../../operations/manual-python-build-handoff.md), a PRODUCER implements, a distinct REVIEWER instance checks the candidate, and a different CLOSURE instance lands and proves accepted work. Model assignments come from one shared runtime source.

**Order of work:** assess each packet independently, revise or split when Agent Ready says so, then release one at a time. Before a release, read back the exact prior work and any relevant active claim. A separate closure owner and the cleanup rules in the hand-fed build plan apply to every packet. The preparation path and live runner already exist as separate Python compositions; their connection requires fixed assessed instructions, a complete reader and separate release authorization. Unit 0 proves the prepared contract and text match the latest assessment. The next unit must save those exact bytes at a fixed, reviewed repository version. Unit 1 makes the reader honor that version; unit 2 publishes it to the queue. Unit 3 brings in a real requirement, unit 4 supplies configurable role assignments, unit 5 enforces quality before acceptance, and unit 6 proves a complete self-building run. The final three units handle temporary-resource prevention, inventory and safe removal.

**Review standard for every change:** the PRODUCER supplies a published exact candidate and concrete checks; the REVIEWER checks it independently for architecture, clean Python, resource lifetime, maintainability, anti-patterns and agent slop, as well as correct behavior. Preserve proof when repairing a finding. A reviewer who cannot retrieve the candidate or reproduce a required check must hold it.

**First factory flywheel claim:** the factory starts from an authorized requirement, prepares its own assessed work, performs a real code change, independently reviews and closes that work, cleans up its temporary resources, recovers from restart and selects the next eligible item. A second pre-seeded task alone does not prove preparation.
