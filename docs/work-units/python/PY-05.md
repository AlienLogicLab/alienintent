## Intent

Connect the offline loop to the real upstream backlog without letting GitHub concepts into the core. Upstream READY work, its Founder-set priority and its dependencies are imported through an Anti-Corruption Layer; authenticated events keep that view current without polling; execution state is projected back as a display only.

## Binding rules — not delegated

1. No vendor payload, node ID, field ID or comment syntax may cross into domain or port signatures. Translation is the adapter's job and is fail-closed on ambiguity, missing membership, unsupported versions or incomplete pages.
2. The imported snapshot is noncanonical: provider/work identity, source version or digest, upstream status, priority, dependencies, product-context provenance and observed time. It never becomes AlienIntent's product backlog.
3. Only an authorized validated release creates an execution. An external edit of a downstream IMPLEMENT/VERIFY/REVIEW/ACCEPT/DONE field is drift, never a lifecycle transition.
4. Projection writes carry a monotonically comparable execution revision and are fenced per target; a stale queued revision must not overwrite a newer projection. Unsupported safe ordering yields a visible unconfirmed outcome.
5. Ingress persists an authenticated receipt before acknowledging custody, validates raw-body authenticity, and routes to exactly one configured profile.
6. No polling. A startup reconcile snapshot is recovery. Bounded reconnect/backoff is not permission to periodically list the backlog.
7. Secrets are references resolved through the SecretProvider port; no secret value is embedded in configuration, diagnostics or evidence.
8. This BIU must not write upstream priority or product state.

## Scope

1. **WorkManagement port** finalised from PY-04's shape, with success, rejection and unavailable outcomes.
2. **GitHub Projects ACL adapter** in `execution_coordination/adapters/`: import READY items with Status mapping, the `Priority` field, native blocked-by dependencies, the BIU contract location and digest, and the Agent-Ready readiness receipt; propose a release; project execution state and revision to configured downstream fields.
3. **EventIngress port and direct-webhook adapter**: authenticated envelope (event identity, schema version, profile/work references, correlation, occurrence/receipt time, provenance, expected version, payload reference), HMAC raw-body verification, durable receipt through the PY-03 inbox, and translation of Project item, Issue and issue-dependency events into neutral upstream-change notifications. Event categories are distinguished: upstream product change, explicit release command, internal execution event, downstream projection receipt.
4. **Startup reconcile**: one snapshot import to re-establish the view after restart.
5. **Typed profile configuration** (minimum viable) in `installation/`: profile identity, repository and Project references, lifecycle/status mapping, release policy, and secret references; plus a **protected-local-file SecretProvider adapter**.
6. **Composition wiring** for a GitHub-backed profile.

## Non-goals / excluded

Outbound relay adapter (FD-04 transport alternative, not required for the Wave 1 minimum); Jira/GitLab adapters; writing upstream priority or product state; worker invocation (PY-06); Decision Inbox projection (PY-07); CLI (PY-08); doctor checks (PY-09); live execution against a real Project (PY-10). No `alienintent init` (SWF-04). No Node, FactoryChecks, credential, deployment or provider-spend change. **No live GitHub mutation is performed by this BIU**; verification uses recorded fixtures and a local server.

## Acceptance criteria

1. Recorded-payload contract tests cover: valid signature accepted; forged signature rejected; tampered body rejected; duplicate delivery returning the prior receipt with no second domain change; reordered stale-version event rejected or held for bounded reconciliation.
2. An imported item with a `Priority` value yields that priority; an item with no `Priority` is imported as unprioritized and scheduled FIFO. `Wave` is imported as metadata only and never affects ordering.
3. Native blocked-by relationships are imported as dependencies; an unsatisfied dependency makes the item ineligible.
4. Ambiguous or unmapped Status values, missing Project membership, and incomplete pagination all fail closed with typed rejections rather than partial imports.
5. An external edit of a downstream execution field produces a drift observation and no lifecycle change.
6. Projection: a newer execution revision is not overwritten by a stale queued write; an unavailable provider preserves internal execution truth and surfaces a projection-delivery failure without changing execution state.
7. Startup reconcile restores the view with no duplicate admission.
8. No secret value appears in configuration dumps, diagnostics, logs or test evidence; a sentinel-leak test enforces this.
9. Fitness checks prove no vendor type crosses a port or domain signature; the Node suite still passes.

## Verification requirements

- Executable proof against recorded GitHub payload fixtures and a locally served webhook endpoint with real HMAC verification.
- Real exit statuses retained; deterministic re-runs.
- Node suite executed and passing.
