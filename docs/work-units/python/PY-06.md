## Intent

Replace the scripted test double with real worker execution, while making it impossible to reach VERIFY without an exact, independently retrievable candidate. Producer and verifier run as separate invocations in separate workspaces, with explicit capabilities and budgets that fail closed.

## Binding rules — not delegated

1. **Custody is enforced by the control plane.** VERIFY is admitted only after the exact candidate is durably identified and proven retrievable by a fresh, independent checkout. Worker instructions are never the enforcement mechanism.
2. A candidate is an immutable artifact identity (exact revision plus provenance), never a mutable branch name alone.
3. Verifier independence is default: separate invocation, owned isolated workspace, independently assembled inputs, immutable candidate/evidence, separate provenance, no access to producer private session state, no self-approval.
4. Private chain-of-thought is neither required nor stored. Observable engineering facts are recorded instead.
5. A grant binds profile, BIU version, invocation/role, issuer, target repository/environment, allowed operations, expiry and budget. Revocation fences new actions and cancels owned work safely.
6. Budget policy follows SWF-09 exactly. A provider that cannot enforce a hard-required dimension is ineligible for that BIU; unreported token/cost is recorded as unknown, never zero.
7. Never reuse a live workspace because a lane looks idle; a cleanup failure is a resource diagnostic, not a rewritten lifecycle result. Never delete a plausibly live workspace or trust a recycled process identity.
8. The Node provider modules are read as behavioural evidence only and are not modified or imported.

## Scope

1. **Workspace port and Git worktree adapter** in `invocation_runtime/`: one workspace per invocation, owner-scoped, with quiescence-checked cleanup.
2. **SourceControl port and Git adapter**: immutable revision identity, candidate publication, and independent read-back from a fresh checkout.
3. **WorkerProvider CLI adapter(s)** wrapping the existing provider CLIs, declaring supported capabilities and the budget dimensions each can enforce, with argument construction that refuses unsafe arguments and requires an explicit permission/sandbox mode.
4. **Capability grants** per FD-03 profiles plus BIU additions, checked at launch and at capability use.
5. **Budget enforcement** per SWF-09: hard wall-clock, attempts, retries, concurrency and cancellation; measured token/cost with explicit unknown; eligibility check that rejects a provider lacking a hard-required dimension.
6. **Cancellation protocol**: fence, signal, confirm quiescence, preserve evidence, clean owned resources, release reservation; late results retained as evidence but unable to undo cancellation.
7. **Bounded retries** with finite attempts, timeout, exponential backoff and jitter, recording attempt and next eligible event.
8. **Custody gate** integrated into the PY-02 guard and the PY-04 loop, plus the verifier invocation path.
9. **Composition wiring** replacing the scripted worker for a real profile, with the test double retained for offline tests.

## Required closure actions

Evaluated under the standing ACCEPT → DONE policy ([SWF-17, SWF-19](../../decisions/2026-09-20-wave1-closure-policy.md)). Closure performs only the minimum remaining actions needed to reach DONE.

- **Landing: required.** A **normal merge commit** of the accepted candidate into `main`, preserving the accepted SHA in `main` ancestry, is **authorized as routine closure** under SWF-19; no separate Founder exception is needed. No rebase, no squash, no rewrite of the accepted SHA, no change to accepted candidate content. If landing would alter accepted content or amounts to a material implementation change, stop and `RETURN_TO_IMPLEMENT`. After landing, run only the required post-merge checks and confirm required CI on the merge result. Merge is a closure operation, not a lifecycle state.
- **Deployment: not required.** No deployable artifact or environment is in scope.
- **Publication/release: not required.** Candidate-branch publication is completed before verification.
- **Live verification: not required.** This BIU has no deployed service or live target in scope; the accepted executable evidence and CI are the required proof.
- **BIU-specific:** none.

Closure must not perform opportunistic refactoring, unrelated cleanup, speculative abstraction, unrelated documentation or tests, architecture redesign, additional feature work, or repeated verification already supported by trusted accepted evidence.

**Minimum necessary work (SWF-20 / SF-REQ-048).** At IMPLEMENT, VERIFY, REVIEW, ACCEPT and closure, perform only the work necessary to satisfy this BIU, its lifecycle obligations, applicable architecture/policy and required evidence. Mechanically detectable over-scope work is a verification finding; REVIEW/ACCEPT assesses unnecessary work, unnecessary abstraction, scope expansion and whether a simpler correct implementation was available.

**Closure evidence (SWF-18).** Record what is available without building new telemetry: closure start/end time; actions evaluated, performed and determined unnecessary; tool/command count; changed files; token/cost where reported; authority interruptions; time blocked awaiting human authority; and any `RETURN_TO_IMPLEMENT` occurrence.

## Acceptance criteria

1. A producer invocation in an isolated worktree produces a candidate; the exact revision is published and read back from a fresh independent checkout before VERIFY is admitted.
2. An unpublished, unreachable or mismatched candidate is refused entry to VERIFY with a typed rejection, proven by negative test.
3. A verifier invocation runs in its own workspace with its own provenance and cannot approve its own production; self-approval is rejected.
4. Capability enforcement: an operation outside the grant is denied; a grant for one target cannot act on another; revocation fences further actions and preserves completed-effect evidence.
5. Budget: exceeding hard wall-clock, attempts or retries stops the invocation and records a bounded outcome; a BIU marking a token or monetary ceiling hard-required rejects a CLI provider that cannot enforce it, with an explicit ineligibility outcome; unreported token/cost is recorded as unknown and never zero.
6. Cancellation mid-invocation terminates the worker safely, preserves evidence, cleans only owned resources and releases the reservation; a repeated cancel is idempotent; an unknown process identity is an explicit unresolved recovery condition.
7. Concurrency: the mutating limit is honoured; a verifier invocation does not consume the mutating slot but counts against global capacity.
8. No secret or credential appears in logs, diagnostics or evidence.
9. Fitness checks and the Node suite still pass; no provider CLI type or vendor concept crosses a port or domain signature.

## Verification requirements

- Executable proof of the real path on a local Git repository with real worktrees and real process launches, including at least one real provider CLI invocation on a trivially bounded task to evidence the adapter contract, and deterministic fakes for the remaining cases.
- Real cancellation and timeout behaviour demonstrated against real child processes, not simulated.
- Retained evidence: candidate revisions, read-back proof, grant and budget records, cancellation evidence, exit statuses, Node suite result.

## Capabilities and budget

Capabilities: repository workspace, Git, Python toolchain, process control, provider CLI execution with an explicit permission/sandbox mode, network only as the provider CLI requires. No deployment, no GitHub mutation, no credential changes.
Budget per SWF-09, with provider spend bounded to the minimum needed to evidence the adapter contract.
