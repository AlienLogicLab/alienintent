### `derive_plan` rules, in this order

1. `MAPPING_UNAVAILABLE`: the mapping is absent, unreadable, digest-mismatched or invalid.
2. `REVISION_MISMATCH`: the mapping names another requirement or another requirement revision.
3. `DESIGN_MISMATCH`: the mapping pins another design revision than `design_ref`.
4. `UNREVIEWED_MAPPING`: the mapping reviewer is not the configured mapping authority.
5. `CIRCULAR_ORACLE`: a predicate has no `derived_from` source, or a source lies under a
   configured implementation root (`src/`, `tests/`, `tools/`).
6. `UNKNOWN_ACCEPTANCE` / `DUPLICATE_OBLIGATION`: a predicate names an AC outside the
   revision, or two predicates share an identity.
7. Completeness:
   - `INCOMPLETE_OBLIGATION`: a MECHANICAL or PLATFORM_ISOLATION predicate lacks the
     statement, fixture, inputs, expected result, endpoint, command, evidence schema or guard.
   - `UNATTRIBUTED_JUDGMENT`: a JUDGMENT predicate lacks the reviewer, inspection inputs or
     decision record.
   - `JUDGMENT_CLAIMS_MECHANICAL_PASS`: a JUDGMENT predicate carries a command or an
     expected mechanical result.
8. `COVERAGE_HOLD`: an acceptance ID of the revision has no predicate. Removing a required
   predicate therefore blocks plan admission.
9. Repair against the prior plan:
   - `PRIOR_OBLIGATION_CHANGED`: a prior obligation is present with a different revision. A
     changed judgment reviewer or inspection input is a changed revision.
   - `PRIOR_OBLIGATION_DROPPED`: a prior obligation is absent.
   - `UNAUTHORIZED_SUPERSESSION`: a supersession is not authorized by the configured
     supersession authority, or its replacement is not in the new plan.
   Each of these holds unless an authorized supersession names that prior obligation and a
   replacement present in the new plan.
10. Platform isolation: each PLATFORM_ISOLATION predicate is read through the U3
    `PremiseEvidenceReader` with its own requested observables. A U3 `InfeasibleProof` (for
    example `UNACHIEVABLE_PREMISE` for `CREDENTIAL_DENIAL`) is returned unchanged, to return
    to source authority. No premise reader returns `PlanHold("PREMISE_EVIDENCE_UNAVAILABLE")`.
11. Otherwise the result is a `ProofPlan` that carries the premise and mapping refs.

A hold never replaces the current plan. It is recorded as a `proof.plan.held` observation
and appended to history. A new plan cites the prior plan's digest, so prior plans stay
retained.

### Battery rules (`evaluate_control`)

The phases must be exactly one each of `intact`, `fault` and `restored`, otherwise
`MISSING_PHASE`. Then:

1. `INTACT_NOT_CLEAN` / `RESTORED_NOT_CLEAN`: that run did not exit 0 with zero applications
   and no failure.
2. `ZERO_APPLICATION`: the fault was applied zero times, so the guard was untriggered.
3. `UNCONDITIONAL_SUCCESS`: the fault run exits 0.
4. `UNRELATED_FAILURE`: the fault run timed out (`exit_status` None), errored, or did not fail
   the named assertion.
5. `OVERDETERMINED`: the fault was applied more than once, or assertions other than the named
   one also failed, so the kill is not attributable to the named guard.
6. Otherwise `QUALIFIED_KILL`.

A self-referential check (its expected result is its own output) can never fail when
faulted. It is therefore refused as `UNCONDITIONAL_SUCCESS`.

### Proof-order rules (ADVISORY, never blocking)

- `proof-order/unresolved-ancestor`: a preceding ref is not in the evidence set.
- `proof-order/missing-plan-ancestry`: a control step has no plan in its ancestry.
- `proof-order/fault-before-intact`: a fault step lacks the same control's intact step.
- `proof-order/restored-before-fault`: a restored step lacks the same control's fault step.

An ordered control yields no diagnostic.

### Repair rules (`evaluate_repair`)

For each prior obligation other than JUDGMENT:

- If the current plan keeps it at the same revision, its replay must be `PASSED`. A missing
  replay is `PRIOR_PROOF_DROPPED`, `SKIPPED` is `PRIOR_PROOF_SKIPPED` and `FAILED` is
  `PRIOR_PROOF_FAILED`.
- If it is superseded, the supersession must be in the current plan (it was authorized at
  derivation), and the replacement replay must be `PASSED`, otherwise
  `REPLACEMENT_PROOF_MISSING`.
- If it is neither kept nor superseded, the result is `PRIOR_OBLIGATION_DROPPED`.

A JUDGMENT obligation is preserved when its revision (reviewer, inputs, decision record) is
unchanged.

## Revision 1: independent-review repair (supplements the text above and removes none of it)

A fresh read-only adversarial review of `1396a16` found no HIGH defect. It found five MEDIUM
and five LOW defects, each reproduced. The repairs refine the pinned behavior as follows:

- **Circular oracle (rule 5).** A source is normalized before the implementation-root test.
  A `repository:` prefix is stripped, `.` and `..` are resolved, and the first component is
  compared case-insensitively. A blank, absolute, backslash, NUL, scheme-bearing or
  repository-escaping source is `CIRCULAR_ORACLE`. Examples are `repository:src/x.py`,
  `docs/../src/x.py`, `SRC/x.py`, `/repo/src/x.py` and `../outside.md`.
- **Completeness (rule 7).** A list field is missing when it is empty or when any item is
  blank. This covers `inputs`, `evidence_schema` and `inspection_inputs`.
- **Supersession (rule 9).** A supersession whose prior obligation is still present, or whose
  prior and replacement are the same, is `INVALID_SUPERSESSION`. This applies to new
  supersessions and to those carried forward from the prior plan. `evaluate_repair` exempts
  an obligation from replay only when it is absent from the current plan, so a live
  obligation is always replayed. As before, `UNAUTHORIZED_SUPERSESSION` is evaluated before
  the changed/dropped checks. The dropped check depends on knowing which supersessions are
  authorized.
- **Vacuous requirement.** A revision with no acceptance IDs, or a mapping with no
  predicates, is `COVERAGE_HOLD`. A requirement ref whose `logical_id` is not the
  requirement ID is `REVISION_MISMATCH`.
- **Mapping adapter.**
  - `schema_version` must be the integer 1 (`true` is refused).
  - Supersession identity, actor and reason fields must be non-blank strings.
  - The review record and each supersession authority record must exist in the repository
    with exactly the pinned sha256. Otherwise the result is `MAPPING_UNAVAILABLE`, never a
    raised `TypeError`.
- **Persisted state.** The pointer must equal the latest `plan` history event, both
  `plan_ref` and `plan_digest`. Every history event must be well-formed. A malformed, foreign
  or lost pointer is `PlanHold("INCOMPATIBLE_PROOF_PLAN_STATE")` from `current`, `derive`,
  `record` and `evaluate_repair`, never an exception. It is never read as an empty history,
  which would skip every prior-obligation check.
- **Tests.** Domain hold assertions now check the type before the reason code, so an admitted
  result fails an assertion instead of raising. The battery tests gain the cases that only the
  named check refuses: a fault that exits 0 while failing the target assertion, and a timeout
  that recorded the target assertion.
- **Additional FX-U4 controls (27 in total):**
  - `prior-proof-drop-accepted` (added before the review, not listed above)
  - `path-normalization-removed`
  - `blank-list-items-accepted`
  - `live-supersession-accepted`
  - `live-obligation-exempted`
  - `authority-digest-unchecked`
  - `pointer-consistency-removed`
  The first trial of the new controls was itself refused by the battery as
  `UNRELATED_FAILURE`. Three tests read `.reason_code` without a type assertion, so the fault
  raised `AttributeError` instead of failing. The battery discriminated that correctly, and
  the tests were repaired.

**Accepted residuals.**

- The supersession field-type guard has no mutation control. Removing it makes derivation
  raise `TypeError`, so the fault surfaces as an error, not an assertion. The unit case covers
  the guard.
- The FX runner's `application_count` is the textual count of the mutation site, and each run
  executes a single test method. The runner therefore cannot itself exhibit
  `ZERO_APPLICATION`, or an overdetermined kill by several assertions. Those battery rules are
  proven by unit cases and by their own mutation controls.
- Some battery checks overlap by design. With `ZERO_APPLICATION` removed, a zero-application
  fault is still refused, as `OVERDETERMINED`, and its control proves the label.
- Authorization of a supersession is the configured actor name plus a digest-pinned authority
  record in the repository. Whether that record truly carries the authority is an independent
  judgment, not a mechanical check.
