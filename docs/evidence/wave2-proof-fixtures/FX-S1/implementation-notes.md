# FX-S1 implementation and evidence boundary

WO-220102 adds a local typed evidence capability. The execution policy and
SQLiteOperationalStore are unchanged. The kernel does not consume these new
records automatically and RAI remains unwired.

## Composed entry points

`EvidenceProfile(evidence_root, permitted_root=..., project=..., name=...,
authority=..., database=...)` builds the repository, service and execution verdict
bridge. An existing `OperationalStore` may replace `database`, but not accompany
it. `OfflineProfile` optionally receives the four `evidence_*` arguments and uses
its existing store. No new upstream profile or inventory application is added.

The operator supplies a preexisting durable parent under the permitted external
root. The repository creates a private evidence directory and `objects` directory,
fsyncs their directory entries, and refuses unsafe permissions/symlink objects.
Objects are limited to 10 MiB by default. Limits may be explicitly configured.
No operational installation path, credential or configuration is stored in Git.

`repository.put(record)` validates structure and retains an inert immutable body;
it does **not** make the record applicable. `service.admit(record,
expected_version)` validates authority and links, installs and reads back the
object, then CAS-appends its exact ref to `upstream:evidence:catalog`. The catalog
separates `(kind, logical_id, revision)` identities; every immutable envelope
retains its role and access label. `service.read()` validates all retained bodies
and reconstructs historical admission in order. It returns a version, exact refs,
records and held definition refs. Old identical puts are no-ops, including after
a newer definition revision is admitted; different bytes at the same identity
are conflicts.

The authority snapshot is an input from the caller's authorized source, never
generated by evidence ingestion. Definition grants pin the exact canonical
record digest, issuer and authority ref. Observation source grants pin source
refs and observer identities; only explicitly trusted grants can satisfy policy.
Evaluator grants pin identity, authority and policy ref. The composed policy ref
is the SHA-256 of the existing `execution_coordination/domain/verdict.py` bytes.
The fixture's synthetic authority and observations are local substitutions, not
product authority or operational verification.

`profile.verdict.evaluate(...)` checks exact current definition and observation
revisions, source/evaluator authority and conflict holds before translating into
the existing `evaluate_verdict`. Only Boolean `true` with no uncertainty and a
trusted source maps to satisfied evidence; `1`, `null` and a worker claim do not.
It returns a typed record, not a lifecycle transition. A verdict admitted through
the service is independently recomputed against the same catalog value used by
CAS. The admission check does not reread recursively or introduce new acceptance
policy. An intervening observation forces either CAS refusal or fresh evaluation.

Historical verdict objects remain retained after later conflicts. Their presence
does not establish current applicability: consumers must use the bridge/current
catalog. The bridge holds if competing observations exist, even if the caller
selects only the positive observation. It never rewrites a requirement or picks
which conflicting observation wins.

## M-EVIDENCE and failure behavior

The migration is additive: version-1 external objects and a new versioned
profile-scoped aggregate; no existing store table or source-authority migration.
A temporary sibling is written and file-fsynced, exclusively linked into the
digest name without overwrite, directory-fsynced, hash-read back, then referenced
by CAS. A pre-CAS process death leaves an unreferenced object; a post-CAS death
leaves a pointer whose exact body is checked on reopen. Tests kill a real child
on both sides of the SQLite commit. They are process-crash tests, not physical
power-loss experiments.

`EvidenceHold` carries a reason, affected refs, evidence refs and required action.
Unknown schemas raise `SchemaIncompatible`; storage errors raise
`StoreUnavailable`. Stale CAS becomes `VERSION_CONFLICT`, with no automatic retry.
Missing/corrupt bodies and incompatible pointers prevent dependent mutation.
Unknown values remain null with a reason. Scalar type and observation order are
preserved; sets are sorted only for canonical encoding.

Rollback may stop using the new composition while retaining all objects and
previous aggregate references. No garbage collection, old-reference rewriting,
automatic schema upgrade, source-authority replacement or live cutover is added.
Export/operator CLI and other DAG-node consumers are outside this bounded S1
fixture; no export of operational/private records is performed. The retained
FX-S1 objects contain only synthetic fixture data.

## Independent local review and repair

A read-only reviewer reproduced two policy/admission defects before publication:
caller-authored ACCEPT over rejected evidence, and admission of an earlier ACCEPT
after a competing observation. Four new regression cases failed with
`DID NOT RAISE` before repair, then passed. The `VerdictAdmission` port checks both
paths; historical evidence remains preserved. The reviewer independently reran
the repaired focused suite: 31 passed.

The same reviewer identified unsynced ancestor directory creation. A new test
failed before repair; the adapter now requires an existing parent, preventing
recursive unsynced creation. This is the bounded alternative to adding a directory
migration mechanism. All findings were implementation repairs within S1, without
changes to acceptance criteria, the policy kernel or prior S0 evidence.
The reviewer reran the 32-test suite after that repair and found no material
remaining blocker. A final mutation regression for caller-owned containers failed
before repair: records and the authority snapshot now detach mutable lists/sets
into tuples/frozensets. The reviewer checked this change and reran the five record
tests successfully.

FX-S1's independent workflow verdict remains **PENDING** until the allocated
VERIFIER retrieves and reviews the published candidate. Local review is not a
substitute for that verdict.
