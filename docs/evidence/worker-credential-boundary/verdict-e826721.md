## The PRODUCER's disclosed gaps
1. The Founder is taken to be the owner of `exports` (operator.py:200). Not blocking. The reader runs as the worker, with the worker's own rights, so a fake worker-owned `exports/<c>/context.json` gives the worker only its own bytes. Nothing privileged is read, and no authority is gained. Like the identity check, this owner check is a consistency check, not a boundary. Learning the Founder's uid from a trusted source would need a new configuration source, which the excluded scope forbids. Suggested cheap hardening for later: also refuse when that owner equals the reader's own uid.
2. `export-refused` is not named in the packet. Acceptable. Check 6d requires a refusal of symlinks, FIFOs and files with a foreign owner, and does not name the code. Giving a refusal its own code, separate from `not-in-export`, is clearer. The worker instruction text names only `not-in-export`, which is a small wording gap.
3. `_export` does not clear an old ACL on an existing `exports/<c>`. Acceptable. The worker has no write on `exports` (Founder-owned, 0711, `--x` only, and the setup removes the default ACL), so only the Founder's user could have made or changed that folder. The owner is checked and the mode is reset on every export.
4. Check 8's `_canonical` does not probe the -wal/-shm files (worker_boundary_check.py:68-73). Acceptable. The setup sets the sidecars to owner-only and probes them as the worker in its final checks (setup_worker_user.sh:98, :162-166). Adding them to 8(a) would make the live proof self-contained. I recommend it, but it is not required by the packet text.
5. A temp file left by a crash blocks the next export under the same pid (work_registry.py:1130, O_EXCL). Acceptable. It fails closed: the export is refused, never a stale or partial file. It needs both the same correlation folder and the same pid, and `<c>` is per invocation.
