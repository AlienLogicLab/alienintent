## What changed

- `tools/fitness/check_architecture.py`: the six existing checks are unchanged. It adds three scoped checks under
  `--check all`:
  - `module-cycle`: every cross-module cycle must be declared in the register, edge for edge.
  - `domain-import`: every cross-module import of another module's `domain` layer must be classified as
    `STABLE_VALUE`, `PORT_CONTRACT` or `DOMAIN_LEAKAGE_HELD`, with a basis.
  - `persistence-ownership`: an SQL table can be mutated only from its declared owning file, and only declared
    owners import `sqlite3`.

  A register entry that matches nothing observed fails as stale, so the register cannot grow into an allow-list. A
  missing register fails closed. `--inventory` emits the observed module graph plus the register as descriptive JSON.
- `tools/fitness/coupling_register.json` records the current source:
  - One acknowledged cycle over five modules and nine edges (Founder finding 4). It is inventoried, not refactored.
  - 23 classified domain imports:
    - `STABLE_VALUE` / `PORT_CONTRACT`: 9, each citing a pinned `shared_contracts` section.
    - `DOMAIN_LEAKAGE_HELD`: 14, where no pinned contract names the object as shared. They are held for ownership
      review, not declared defects.
  - One persistence owner: `SQLiteOperationalStore`, seven tables.

  It is not an allowed-edges table: an edge outside a cycle needs no entry.
- Design admission (`context_assembly/domain/design_admission.py`) now runs checks in this order:
  1. `existing-architecture`
  2. `scoped-coupling` (new)
  3. interface, completeness, decisions, premise
  4. `direction-authority`

  Once the gap is disposed, declared edges are judged by rules:
  - `FORBIDDEN_DEPENDENCY`: an inner layer importing adapters, or a private product.
  - `UNDECLARED_CYCLE`: the edge closes a cycle that is not declared.
  - `UNCLASSIFIED_DOMAIN_IMPORT` / `DOMAIN_LEAKAGE`: holds for classification.
  - `UNRESOLVABLE_DEPENDENCY` / `COUPLING_EVIDENCE_UNAVAILABLE`: explicit holds.

  Rule violations and `INCOMPATIBLE_INTERFACE` report `FAIL`. Classification gaps report `HOLD`. Either way,
  `record_review` refuses VERIFIED with `MECHANICAL_HOLD_OUTSTANDING`. No new lifecycle state was added.
- Composition (`composition/design_admission.py`):
  - `RepositoryArchitectureChecks` also runs the coupling checks and reads the inventory. The register bytes are
    part of the architecture baseline, so reclassifying makes a verified design `STALE`.
  - `RetainedDirectionAuthority` reports `FOUNDER_DISPOSED` only for exactly one `RESOLVED` resolution whose
    authority document is readable and names the gap. That document's digest enters the authority vector.
    Otherwise the status is `UNAVAILABLE`.
