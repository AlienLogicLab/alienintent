### Fixture inputs (durable state only; `tmp_path` or `--output` root, never a live profile)
- **Store.** One `SQLiteOperationalStore` (`execution_coordination/adapters/sqlite_store.py`) holding these aggregates:
  - `factory:<id>` and `release:<id>` (`FactoryCoordinator` encoding of `ExecutionState`/`LifecycleStage`). Seed at least IMPLEMENT, VERIFY, DONE and an authority-blocked item.
  - `decision-inbox`: open `HumanDecisionRequired` via `DecisionInbox.register`.
  - `attention:*` items in PENDING, SEEN and RESOLVED. These come from C1 `AttentionProfile` (`composition/control_plane_profile.py`) with injected clock and IDs.
  - `upstream:requirements:current`: a U1 `InventoryService.publish` pointer.
- **Evidence.** A `LocalEvidenceRepository` (`evidence_learning/adapters/local_evidence_repository.py`) holds the S1 `Observation` bodies that those pointers reference.
- **Manifest (PLANNED).** An immutable S1 `Observation` (`evidence_id="context.manifest"`) lists, for every authoritative record: aggregate key, store version, canonical-state sha256 and S1 `Ref`. It is installed and read back before CAS of a derived pointer. This is the same pattern as `InventoryService.publish`.
- **Durable event.** The fixture's durable event is a committed store transition, applied before the predecessor stops. For example, `AttentionService.ensure` of a DONE origin, or a `factory:` commit. See U-3.
- **Transcript control input.** A `transcript.jsonl` file and a `ALIENINTENT_CONVERSATION` environment value inside the profile root. Both contain contradictory "next action" prose.

### Probes and expected observables (SF-REQ-053-AC-01)
| Probe (test id, PLANNED) | Expected |
|---|---|
| `test_fresh_invocations_equal` | Predecessor stops after the durable event, then successor A and successor B run. All three produce byte-equal canonical reconstruction documents (the six fields plus `lifecycle`), and the outputs carry equal digests. |
| `test_mismatch_is_failure` | A planted store change after pinning yields `MISMATCH`, listing the differing fields and exiting nonzero. A process that started successfully is never counted as PASS. |
| `test_conversation_not_input` | Present versus absent `transcript.jsonl` / `ALIENINTENT_CONVERSATION`: output digests are equal, and no reconstruction `input_refs` names the transcript. |
| `test_list_order_independent` | A `list_states` order reversed between invocations still gives equal output. |
| `test_seen_is_not_resolved` | A SEEN attention item stays in `blocked_set`/`pending_attention`. DecisionInbox entries appear only in `unresolved_decisions`. |
| `test_unavailable_state_holds[...]` | Each of these returns a typed `ContextHold` with the reason and affected refs: missing aggregate, version drift from the manifest, digest mismatch, unreadable or absent evidence body, `StoreUnavailable`, malformed `decision-inbox` shape, or `InventoryHold`. The action set is never empty and never guessed. The runner exits 2 (HOLD), consistent with the FX-S0 hold convention. |

### Discriminating controls (intact exit 0 → fault exit 1 at the named assertion → restored exit 0; `application_count` 1)
| Control | Mutation (disposable copy) | Failing probe |
|---|---|---|
| `manifest_digest_pin` | skip the per-record digest comparison | `test_unavailable_state_holds[digest]` (DID NOT RAISE) |
| `missing_record_hold` | replace the hold on a missing aggregate or evidence body with an empty default | `test_unavailable_state_holds[missing]` |
| `store_unavailable_hold` | catch `StoreUnavailable` and return empty sets | `test_unavailable_state_holds[store]` |
| `version_fence` | ignore store version versus manifest version | `test_unavailable_state_holds[drift]` |
| `canonical_order` | remove the canonical sort | `test_list_order_independent` |
| `conversation_isolation` | fold transcript/environment text into the action derivation | `test_conversation_not_input` |
| `context_item_omitted` | drop `evidence_refs` (or one manifest item) from the output. This is the design's 053-tenure-fence "omit context item" proven-red. | `test_fresh_invocations_equal` |
| `mismatch_as_failure` | make the comparator always return equal | `test_mismatch_is_failure` |
| `seen_not_resolved` / `queue_distinct` | treat SEEN as resolved / merge attention into decisions | `test_seen_is_not_resolved` |

A non-discriminating mutation, an `application_count` other than 1, or a missing observation is
a HOLD, not a PASS. Controls that can only fail by hanging are not counted. They are recorded as
residuals, as FX-U3 did.
