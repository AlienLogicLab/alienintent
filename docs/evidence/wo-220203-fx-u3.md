## Behavior (pinned before implementation)

- **Neutral domain values.** `evidence_learning/domain/premise.py` defines
  `IsolationObservable` (the four observables only), `PremiseObservation`,
  `PlatformIsolationPremise`, `InfeasibleProof` and `evaluate_isolation_premise`. No credential
  denial observable exists.
- **Ports.** Port `evidence_learning/ports/premise_evidence.py` `PremiseEvidence.observe()`
  returns `RetainedPremiseEvidence`: the target, the doctor state, the observations and the
  unavailable-artifact findings, all as neutral values.
- **Application.** `evidence_learning/application/premise_service.py`
  `PremiseEvidenceReader.read(premise_id, requested) -> PlatformIsolationPremise | InfeasibleProof`.
- **Composition.** `composition/premise_evidence.py` `RetainedDoctorPremiseEvidence` implements
  the port at the outer boundary. It reads the mapping and the artifacts, verifies the pinned
  digests, and imports `REQUIRED_CHECKS` from the unchanged installation doctor.
  `UpstreamProfile` accepts an optional `premise_evidence` and exposes `profile.premises`. The
  existing constructor stays compatible.
- **Import boundary.** The new `evidence_learning` modules import neither `installation` nor
  `composition` (the `premise_bridge` shared contract, asserted for these modules only).

`read` returns `InfeasibleProof(reason_code, missing, evidence_refs, required_action="return
the premise to source authority")`, and never an invented observation. The reason codes are:

- `UNACHIEVABLE_PREMISE`: the request names any observable outside the four, for example
  `CREDENTIAL_DENIAL`.
- `INCOMPLETE_PREMISE_REQUEST`: the request omits one of the four observables.
- `DOCTOR_EVIDENCE_UNAVAILABLE`: the doctor precondition is absent or not PASS.
- `TARGET_MISMATCH`: an observation's target differs from the configured target.
- `MISSING_PREMISE`: an observable has no retained observation. This includes an artifact
  that is missing, fails its digest check or cannot be parsed, and a mapped check that is
  absent.
- `UNSATISFIED_PREMISE`: a mapped observation is present but not satisfied. For checks, the
  retained `ok` is not exactly `true`. For readback, a value is absent or differs.

Otherwise `read` returns `PlatformIsolationPremise` carrying every observation. Each
observation carries an S1 `Ref` to the digest-pinned artifact, with locator
`repository:<path>#<check-or-pointer>`.

## Revision 1: independent-review repair (supplements the text above and removes none of it)

A fresh read-only adversarial review of `dc6d16d` found five MEDIUM and seven LOW defects. The
repairs refine the pinned behavior as follows:

- **Premise identity.** The mapping's `premise_id` is now bound. Reading any other premise id
  returns `PREMISE_MISMATCH`, so sandbox evidence cannot be relabeled as some other premise.
- **Mapping pin.** Composition supplies the mapping's expected sha256
  (`RetainedDoctorPremiseEvidence(root, mapping_path, mapping_sha256, project, profile)`). Both
  result types cite the mapping `Ref`. The following all return `MAPPING_UNAVAILABLE` and never
  raise:
  - a missing, unreadable, digest-mismatched or schema-invalid mapping
  - an unknown observable such as `CREDENTIAL_DENIAL`
  - an entry that names an undeclared artifact
  - an entry that has neither `check` nor `unchanged`
  - a missing `doctor` section
- **Mapping revision.** The revised mapping sha256 is `8f6c9f063a934a8c63ea724fb1c554154cdd6bf8a70b250a0d06d09480b2ba23`.
  - `no_project_identity_other_than_the_configured_one_appears_in_configuration` is excluded,
    because `tools/live/py09b_live_checks.py` records it unconditionally `ok=true`, and
    SF-REQ-014-AC-02 refuses unconditional-success checks. `PROFILE_SCOPING` keeps two
    discriminating checks. AC-U3-01 now expects **8** observations.
  - Detail predicates are pinned where the live tool has a vacuous pass. `delivery_for_another_project_is_refused`
    requires `replayed a real delivery` and `status_code=401`.
    `project_identity_resolution_fails_closed_on_mismatch` requires
    `typed outcome ProjectAddressRejected`.
- **Readback.** On either side, an absent, `null`, `false`, empty string or empty container
  value means nothing was read, which is not an unchanged state. The result is
  `UNSATISFIED_PREMISE`.
- **Robustness.**
  - An unreadable artifact, a non-string doctor `detail` or duplicate JSON keys (in an
    artifact or in the doctor outcomes) become gaps, never exceptions.
  - An artifact whose target cannot be read records `target:<key>` and yields
    `MISSING_PREMISE`.
  - `UpstreamProfile` raises `ValueError` if only one of `premise_evidence` or
    `premise_target` is supplied. Existing callers are unaffected.
  - The import-boundary test also rejects relative imports.
- **Additional FX-U3 controls (18 in total):**
  - `doctor-required-checks-removed` (added before the review; it was not listed above)
  - `premise-identity-unbound`
  - `mapping-pin-removed`
  - `mapping-validation-removed`
  - `empty-readback-accepted`
  - `detail-predicate-removed`
  - `duplicate-key-accepted`
  - `absent-target-accepted`

**Accepted residuals.**

- The PY-09B top-level aggregate `ok` is not a mapped predicate, so it is not consulted. Each
  mapped check is judged individually.
- The equal before/after values are not shape-checked beyond being read. For example, a
  malformed digest string that is equal on both sides passes. Shape checking would need a
  per-pointer shape predicate that the authority has not reviewed. The artifact digest pin
  and the independent VERIFIER judgment cover this.
